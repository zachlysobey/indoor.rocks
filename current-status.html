Dig deeper

The one blocker, precisely — and how it was cleared

src/app/page.tsx rendered <DataRenderer dataPromise={getUserData()} />. That server action imported src/db/drizzle.ts, which throws at module load if DATABASE_PW is unset. Next.js tries to statically prerender / at build time, so the throw killed the build:

✓ Compiled successfully
   Collecting page data ...
Error: make sure to export DATABASE_PW!
> Build error occurred
Error: Failed to collect page data for /

Nothing on the site used that data — it rendered an empty array of users. It was a “can I talk to Postgres from a server action” spike.

Cleared in PR #3: removed src/db/, src/actions/todoActions.ts, migrations/, drizzle.config.ts, the <DataRenderer> usage, and the drizzle-*/pg/dotenv dependencies. All of it is preserved on the park/database branch, documented in issue #2. Build now emits 5/5 static pages; lint is clean. Dropping drizzle-kit also took its esbuild advisories off main.
